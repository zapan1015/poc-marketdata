# 증권사 초저지연 시세/FDS 아키텍처 PoC 참조 문서

## 1. 아키텍처 개요

본 아키텍처는 고빈도 시세(Market Data Tick) 수신, 실시간 인메모리 최신 시세 갱신(LWW), 초저지연 팬아웃(Fanout), 대용량 틱 저장 및 이상 거래 탐지(FDS) 감사를 위한 초저지연 파이프라인을 검증합니다.

```
+-------------------------------------------------------------------------+
|                              Traffic-Gen                                |
|  (Tier 0: 1K, Tier 1: 10K, Tier 2: 100K, Tier 3: 300K TPS / Zipf 분포)  |
+------------------------------------+------------------------------------+
                                     |
                          market.tick.raw (Kafka API)
                                     v
+-------------------------------------------------------------------------+
|                        Redpanda (Kafka API 호환)                        |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
|                        Materializer (Go 서비스)                         |
|   - Redpanda Consumer Group                                             |
|   - 격리성 구조: NATS 즉시 발행 + ScyllaDB 비동기 워커 풀               |
+-------------------+---------------------------------+-------------------+
                    |                                 |
      market.<symbol> (NATS Core)         USING TIMESTAMP ? (LWW)
                    v                                 v
+-----------------------+                 +-------------------------------+

```

## 2. 주요 설계 원칙

### 2.1 스토리지 레벨 Last-Write-Wins (LWW)
- 시세 피드에는 네트워크 지연이나 멀티 피드 합산으로 인해 순서 역전(Out-of-Order)이 발생할 수 있습니다.
- ScyllaDB 쓰기 시 `USING TIMESTAMP <exchange_ts_us>` 구문을 적용하여, 과거 시각 이벤트가 나중에 도착하더라도 스토리지 엔진 레벨에서 자동으로 무시되도록 처리합니다.

### 2.2 실시간 경로와 저장 경로의 격리성 (§3.3)
- ScyllaDB 또는 ClickHouse의 GC, 디스크 I/O 병목, 장애 발생 시에도 실시간 클라이언트 시세 분배(NATS 경로)는 영향을 받지 않아야 합니다.
- `materializer`는 NATS 발행을 동기/직렬 체인에서 즉시 수행하고, ScyllaDB 쓰기는 바운디드 버퍼 큐와 워커 풀을 통해 비동기 처리하여 장애를 완벽히 격리합니다.

### 2.3 지연 예산 (Latency Budget)
- 목표: **Feed(생성) → Redpanda → Materializer → NATS → Probe 수신 전체 구간 p99 < 10ms**
- Tier 1 (10,000 TPS): p99 < 5ms 기대
- Tier 2 (100,000 TPS): p99 < 10ms 유지
- Tier 3 (300,000 TPS): 피크 구간 p99 < 20ms 이내 방어

## 3. WSL2 환경 특화 가이드

1. **디스크 I/O 최적화**: Windows 드라이브(`/mnt/c/...`) 마운트를 지양하고, 컨테이너 볼륨을 Docker 기본 볼륨(ext4 내부 관리)으로 설정.
2. **메모리 한계선 설정**: `.wslconfig`에 `memory=20GB`, `processors=8`을 적용하여 Windows 호스트와의 리소스 경합 방지.
3. **가상 디스크 압축**: 대량 부하 테스트 후 `scripts/compact_vhdx.ps1`을 실행하여 ext4.vhdx 크기 최적화.
